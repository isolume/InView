# Student Center East assets

`student-center-east-floor-2.json` preserves the exact bytes of the supplied `venue-map 3.json`. The user confirmed this scan is Floor 2. Its map coordinates are the original scan coordinates, in meters. It contains 77 footprints, including 12 measured floor regions, and two manually labeled elevators. It represents a scanned area, not complete building coverage. Floors 1 and 3 have no bundled measured routing maps.

The default visual resources `student-center-east-floor-2-model.usdz` and `student-center-east-floor-3-model.usdz`, their individual PNG previews and `student-center-east-model-layout.json` preserve the exported assets from `models/walkthrough-building/floors-2-3/`. They reconstruct the filmed portions of Floors 2 and 3, including estimated connecting spaces. All dimensions, furniture spacing, topology and inter-floor alignment remain estimates. Closed rooms and unfilmed wings are not modeled. Floor 1 has no visual model. The earlier atrium asset remains in the source model folder and its earlier app resource copies, but is no longer the default.

Both visual floors share a first approximate registration between the new Floor 2 model's elevator-door centers at `(-1.30, 0, 8.82)` / `(1.07, 0, 8.82)` and the original map's elevator markers. The same rotation, uniform scale and translation apply to both assets. Floor 2 is authored at Y = 0 and Floor 3 retains its estimated Y = 4 meters; the per-floor display plane is computed under that registration. It fits the two elevator landmarks; other geometry remains estimated, including gaps in the scan. It never changes the source map, routing, clearance decisions or live AR registration. The transform lives in `StudentCenterModelAlignment.swift`.

Layout labels are display-only landmarks with stable IDs derived from their floor and title. They are not routing access points. `estimatedScene(for:)` supplies an empty, explicitly estimated canvas source containing no measured surfaces, objects or floor coverage; the USDZ itself supplies the visual geometry. This permits Floor 3 browsing while the measured map remains absent.

`student-center-east-floor-2-scene.json` is prepared display geometry derived from this exact map through `VenueScene`, world-outline-to-local-polygon conversion, `IndoorFloorContent` selection and `FinalMapSceneBuilder`. It retains scan coordinates and provides the measured map's cutaway view without rebuilding furniture on first launch. It is a display cache; the original map stays authoritative for routing and annotations. The cache has 62 surfaces and 16 display objects, with no raw mesh or point-cloud layer.

For the Floor scan layer, each object uses one simple measured box instead of baked furniture templates. Source IDs, categories, poses, measured dimensions, obstacle corners and obstacle bounds are preserved, as are all measured surfaces and floor outlines. This display-only simplification makes the initial map lightweight; the alternative USDZ layer supplies the detailed visual reconstruction.

The supplied map has no saved ARWorldMap or geographic registration. These assets permit map browsing and visual exploration without enabling live AR positioning. Elevator labels do not establish verified connections to other floors.

The native catalog also validates imported or published maps before rendering. It accepts building-scale geometry with finite, bounded coordinates, a maximum 500-meter map span, unique identified features and nondegenerate floor outlines. Geometry beyond those limits requires partitioning into smaller floor maps.
